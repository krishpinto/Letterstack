# Infrastructure

Where each production service lives, and which environment variables come from it.
All production values are set in Vercel (project `letterstack`). Every variable there
has a comment that names its source. Production values are marked "sensitive", so they
cannot be read back. To change one, generate a new value at the source and paste it in.

| Service | What it does | Where to manage it | Variables |
|---|---|---|---|
| Vercel | Hosting, builds, environment variables | Project `letterstack` | — |
| Neon | Postgres database | Project `blue-glitter-63644869`, branch `production` | `DATABASE_URL` |
| AWS SES (ap-south-1) | Sends email | IAM user for the app, SES configuration set | `AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `SES_CONFIGURATION_SET`, `MAIL_FROM` |
| AWS SNS | Delivers SES bounce, complaint and delivery events | Topic `letterstack-ses-events` | `SES_EVENTS_TOPIC_ARN` |
| Upstash QStash (US region, us-east-1) | Queues sends, automations and scheduled campaigns | QStash → US Region | `QSTASH_URL`, `QSTASH_TOKEN`, `QSTASH_CURRENT_SIGNING_KEY`, `QSTASH_NEXT_SIGNING_KEY` |
| Google Cloud `letterstack-prod` | "Sign in with Google" | Google Auth Platform → client `LetterStack Sign-in (prod)` | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` |
| Google Cloud `letterstack-gmail` | "Send from my Gmail" | Google Auth Platform → client `LetterStack Gmail Sender (prod)` | `GOOGLE_GMAIL_CLIENT_ID`, `GOOGLE_GMAIL_CLIENT_SECRET` |
| UploadThing | Image uploads and CDN | App `LetterStack` → API keys | `UPLOADTHING_TOKEN` |
| Razorpay (live) | Payments | Account & Settings → API keys, Webhooks | `RAZORPAY_KEY_ID`, `NEXT_PUBLIC_RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET` |
| GoDaddy | DNS for `letterstack.site` | Domain DNS records | — |

Variables generated by us, not by a service:

| Variable | Purpose | Notes |
|---|---|---|
| `AUTH_SECRET` | Signs login sessions and Gmail connect state | Rotating it signs everyone out. Unsubscribe links also use it until `UNSUBSCRIBE_SECRET` is set. |
| `UNSUBSCRIBE_SECRET` | Signs unsubscribe links | When you set it, give it the current `AUTH_SECRET` value, or links in emails already sent stop working. |
| `MAILBOX_ENCRYPTION_KEY` | Encrypts connected Gmail refresh tokens | Do not rotate. Rotating it disconnects every Gmail sender. |
| `ADMIN_EMAILS` | Who can open `/internal` and `/admin` | Comma-separated. |

## Google OAuth

The two Google projects are separate on purpose. The Gmail project requests the sensitive
`gmail.send` scope, and Google must verify that before more than 100 users can connect.
Sign-in only uses basic scopes, so it needs no verification. Keeping them apart means
the Gmail review can never block sign-in.

Redirect URIs:

- Sign-in: `https://letterstack.site/api/auth/callback/google`
- Gmail: `https://letterstack.site/api/senders/gmail/callback`

## Webhooks into the app

| Source | Endpoint | Verified by |
|---|---|---|
| Razorpay | `/api/payments/webhook` (`payment.captured`, `payment.failed`, `refund.processed`) | `RAZORPAY_WEBHOOK_SECRET` |
| AWS SNS | `/api/webhooks/ses` | SNS message signature and `SES_EVENTS_TOPIC_ARN` |
| QStash | `/api/send/*` | QStash signing keys |

## Rotating a key without downtime

- **QStash:** use "Roll Signing Key" (the old next key becomes current, which the app
  already accepts). Then "Reset Token", update Vercel, redeploy, and press "Rotate Tokens".
- **Google:** "Add secret" on the client, update Vercel, redeploy, then disable the old secret.
- **UploadThing:** create a key, update Vercel, redeploy, then delete the old key.
- **Razorpay:** "Regenerate key" logs out the old key immediately, or after 24 hours if
  you choose that option. Update Vercel and redeploy straight away.

Vercel only reads new variable values at build time, so redeploy after every change.
